# ceo/HANDOFF_TEMPLATE — шаблон выдачи задач агенту

Копируй блок ниже, подставь значения, и отправь агенту (в чат / issue / PR-комментарий).
Главное: **ссылка на репо + указание, где твои задачи** — чтобы агент сразу понял контекст без пояснений.

```
Кому: агент-<track>  (напр. agent-frontend-01)
Роль: <frontend | backend | content | qa | admin>

Ссылка на репо: https://github.com/<owner>/<repo>
Старт (обязательно прочитать по порядку):
  1) github_project/README.md
  2) github_project/05_AGENT_PROTOCOL.md
  3) github_project/04_STATUS_LOG.md   ← смотри статус

Твои задачи: github_project/tracks/<track>.md
  Начни со следующей todo (или группы подряд идущих):
  - T### <название>
  - T### <название>
  (бери по порядку; зависимости уже approved)

Что сделать: <кратко: реализовать X по файлу задачи, соблюсти стек>
Стек: строго по github_project/02_TECH_STACK.md (нет обходных путей; если недоступно — blocked + пропуск/стоп)
Статус вести в: github_project/04_STATUS_LOG.md (и в файле задачи, раздел «Лог»)

Как проверить вручную: <npm run dev → экран → действие>
После серии задач: один PR «Closes T###, T###, T### — <суть>»
Кто проверит: CI + Reviewer Agent; если задача с 🔴 — ждёт твою (CEO) визуальную приёмку.
```

## Вариант: «выполняй следующую по плану»
Если агент уже работает и закрыл задачу: просто скажи «выполняй следующую по плану» —
агент берёт следующую `todo` в своём треке/фазе, продолжает в той же ветке, и в конце один PR закрывает несколько подряд идущих задач (`06_REVIEW_WORKFLOW.md` §3).

## Вариант: раздельная выдача фронта и бэкенда
Двум агентам одновременно:
- Агенту А: ссылка + `github_project/tracks/frontend.md` (начни со следующей todo).
- Агенту Б: ссылка + `github_project/tracks/backend.md` (начни со следующей todo).
Они идут параллельно (фазы 1 и 10 после фазы 0), пересекаясь только через `shared/` (схемы/контракты).
