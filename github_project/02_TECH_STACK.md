# 02 · TECH STACK — архитектурные ограничения

## Зафиксированный стек

| Слой | Технология | Обязательство |
|---|---|---|
| Клиент | Phaser 4 + TypeScript strict + Vite | единый WebGL game canvas |
| Игровой UI | rexUI + Phaser Graphics/Text | без React и без DOM как основы игрового UI |
| График | собственный `CandleChart` на Graphics | без TradingView/lightweight-charts widgets |
| Состояние | Zustand vanilla store | без React bindings |
| Домен | seedrandom + чистый scenario-gen | воспроизводимость по `scenarioId + contentVersion` |
| Сервер | Fastify + SQLite + Drizzle + Zod + WebSocket | типизированные контракты и realtime турниров |
| Звук/PWA | Phaser Sound + vite-plugin-pwa | настройки mute/reduce-motion, offline shell |
| Проверки | Vitest + Playwright | unit/contract/e2e и UI matrix |

Конкретные версии фиксируются lockfile в `T000` после проверки совместимости. Документация не должна заявлять непроверенную точную версию как факт.

## Инварианты важнее названий библиотек

- Скрытый future не попадает к клиенту до фиксации решения.
- Сценарий детерминирован и версионирован.
- Оценка качества не равна направлению цены или PnL.
- Общие контракты живут в `shared/`, а не копируются между пакетами.
- UI остаётся доступным: смысл дублируется текстом/формой, touch target ≥44×44.
- Арт грузится по pack и не блокирует первый интерактивный сценарий.

## Протокол несовместимости

Запрещена **молчаливая** подмена технологии. Но агент обязан сначала диагностировать проблему, а не объявлять `blocked` после первой ошибки установки.

1. Записать окружение, команду, версию и полный текст ошибки.
2. Проверить lockfile, peer dependencies, официальную документацию и минимальный пример.
3. Отделить проблему сети/прав/локального кеша от реальной несовместимости API.
4. Если исправление сохраняет стек и инварианты — применить и покрыть тестом.
5. Если требуется смена стека или нарушение инварианта — `blocked` с доказательством и ADR/issue для решения владельца.

Недопустимые production-подмены без отдельного архитектурного решения:
- Phaser 3/Unity/Godot вместо Phaser 4;
- React/DOM overlay как основной игровой UI вместо rexUI/Phaser;
- готовый web-chart вместо `CandleChart`;
- `Math.random()` или время системы в детерминированной доменной логике;
- отправка скрытого future клиенту с надеждой «спрятать» его интерфейсом;
- polling вместо WebSocket в турнирном realtime-контракте.

## Заглушки

Разрешены только там, где они явно не искажают продукт:
- отсутствующий необязательный raster art → manifest `placeholder: true` и кодовая/SVG-заглушка;
- контент до фазы 11 → небольшой версионированный fixture pack в `shared/fixtures/`;
- платежи → интерфейсный stub без реальной транзакции и без влияния на игровой результат.

Заглушка должна быть помечена в коде/manifest и иметь задачу на замену. Она не может скрывать невыполненный acceptance criterion.
