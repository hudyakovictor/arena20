## Что это (для будущего)
Из исходного брифа: отдельная папка `admin/` — панель, из которой ведётся управление игрой как контентом, и куда стекаются все данные из игры (CRM).
Реализуется **отдельной итерацией** после релиза одиночного продукта (фаза 13, задачи `T130`/`T131`), не блокирует MVP.

## Модули (набор для будущей админки)
1. **Content Studio** — сценарии, карты навыков, сущности, протоколы, теория; редактор content-pack с валидацией по `shared/` Zod; версионность датасета + хэш скрытого future.
2. **Analytics / CRM** — данные игроков: прогресс, профили повторяющихся ошибок, журналы решений, удержание; источник — `server/`.
3. **Economy / Market Admin** — косметика, темы, сезонные наборы; без продажи преимуществ (product-mechanics-spec §13).
4. **Tournament Admin** — создание/фиксация server-side seed, лидерборды, античит-логи.
5. **Localization** — управление copy-keys (RU+EN, архитектура под 10+ языков), tone-of-voice линт.

## Подключение AI-API — отдельная будущая задача (НЕ сейчас)
В брифе было: в админке предусмотреть подключение API AI-моделей, чтобы позже фронт-работы распределялись между агентами как «компания из отделов и чатов».
Это **не то же самое**, что текущая агентная разработка через GitHub. Здесь мы только **оставляем архитектурное место** под это (модуль AI Studio, провайдеры через единый адаптер, ключи в secrets, очереди генераций), но саму оркестрацию агентов через CRM проектируем в **отдельной задаче**, когда игра уже работает. Не проектируй её как часть того, как агенты строят игру сейчас.

## Архитектура (будущая)
- Отдельный пакет `admin/` (свой фреймворк по решению CEO; не обязан быть на Phaser).
- Читает/пишет данные через тот же `server/` (Fastify/Zod/WS) — единый контракт `shared/`. Никакого прямого доступа к БД вне сервера.
- RBAC позже: CEO — полные права; остальные роли — свои разделы.
