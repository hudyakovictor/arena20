# SIGNAL ARENA · `github_project`

Эта папка — **инструкция для ИИ-агентов** и **техническое задание (ТЗ)** на реализацию игры SIGNAL ARENA.
Работа ведётся через GitHub: любой агент заходит по ссылке на репозиторий, читает этот раздел и берёт задачу.
Всё устроено так, чтобы при передаче задачи от агента к агенту (один не потянет весь объём) новый агент сразу видел статус и что делать дальше — без пояснений от человека.

> 📌 **Где информация по самой игре?** Исходники (прототип, продуктовые спецы, иконки, бренд) лежат прямо в **`github_project/source/`** — рядом с инструкциями, чтобы агент видел всё внутри проекта (оригиналы также в корне репо). Карта исходников: [`SOURCE_MATERIALS.md`](./SOURCE_MATERIALS.md).

## Кто здесь главный
- **Генеральный директор (CEO)** — единственный человек в проекте. Может вмешаться в любой процесс, но без него вся работа функционирует между агентами.
- **Агенты** — исполнители задач. Каждый берёт задачу из `github_project/tasks/`, делает, обновляет статус в `04_STATUS_LOG.md`, открывает PR. Работают через GitHub; будущая CRM с AI-API — **отдельная задача**, не часть текущей разработки (см. `admin/ADMIN_ROADMAP.md`).

## С чего начать (30 секунд для любого агента)
1. `README.md` (этот файл) — что где лежит.
2. `INDEX.md` — карта всех документов и задач.
3. `05_AGENT_PROTOCOL.md` — как взять задачу и отчитаться.
4. `04_STATUS_LOG.md` — что сейчас в работе / что готово.
5. `tasks/T###_*.md` — конкретная задача, которую предстоит сделать.

## 🔴 Золотое правило (читать обязательно)
Стек **зафиксирован**. Phaser 4 + TypeScript + Vite, rexUI, кастомный `CandleChart` на Graphics, Zustand (без React), seedrandom + свой scenario-gen, Fastify + SQLite + Drizzle + Zod + WS, Phaser Sound, vite-plugin-pwa, Vitest + Playwright.

Если какой-то механизм из стека **недоступен** агенту (нет в реестре, не ставится, заблокирован) — **запрещено искать обходной путь и подменять его другим**.
Агент обязан либо **пропустить этот участок** и идти дальше к независимому, либо **остановить работу**, если продолжение невозможно без завершения данного участка со указанным стеком. Блок фиксируется в статус-логе.
Подробнее: `02_TECH_STACK.md` и раздел «Правила исполнения» в `05_AGENT_PROTOCOL.md`.

## Рабочая папка проекта (где живёт код)
- `client/` — игра (Phaser 4 + TS + Vite).
- `server/` — бэкенд (Fastify + SQLite + Drizzle + Zod + WS).
- `admin/` — админ-панель и CRM (собирается **отдельной будущей итерацией**, см. `admin/ADMIN_ROADMAP.md`).
- `shared/` — общие Zod-схемы, типы, дизайн-токены, движок сценариев (используются и клиентом, и сервером).

## Как обновлять статус
`_meta/tasks.json` — единственный источник правды. Файлы в `tasks/`, `tracks/`, `03_MASTER_PLAN.md` и `04_STATUS_LOG.md` генерируются и вручную не редактируются.

```bash
python3 github_project/_meta/generate.py set-status T000 in_progress --agent <id> --note "что начато"
python3 github_project/_meta/generate.py check
```

> Любой агент, получивший ссылку на репозиторий, должен понять всё без дополнительных пояснений. Если чего-то не хватает в доках — это баг документации, поправь её в том же PR.
