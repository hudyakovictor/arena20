# 07 · TRACKS — разделение работы на треки (фронт/бэк/контент/qa)

Работа делится на треки, чтобы CEO мог выдавать агентам **«ссылка + твои задачи по фронту/бэкенду»** и чтобы фронт и бэкенд шли **параллельно и независимо**.

## Треки
| Трек | Что внутри | Файл |
|---|---|---|
| `foundation` | Каркас репозитория, конвенции (фаза 0) | [tracks/foundation.md](./tracks/foundation.md) |
| `shared` | Схемы, токены/манifest, движок сценариев, оценка (фазы 0,3,4-shared). Без React | [tracks/shared.md](./tracks/shared.md) |
| `frontend` | Phaser 4 игра: shell, график, Арена, Академия, Угрозы, Журнал, Турниры, Маркет, i18n (фазы 1,2,4–9,12) | [tracks/frontend.md](./tracks/frontend.md) |
| `backend` | Fastify/SQLite/Drizzle/Zod/WS сервер (фаза 10) | [tracks/backend.md](./tracks/backend.md) |
| `content` | Авторство контента и copy (фаза 11) | [tracks/content.md](./tracks/content.md) |
| `qa` | Тесты, бюджеты, матрица UI, i18n-гейт, релиз (фазы 0,2,3,4,10,12,13) | [tracks/qa.md](./tracks/qa.md) |
| `admin` | Админ-панель и CRM, AI-API (фаза 13, план) | [tracks/admin.md](./tracks/admin.md) |

## Как CEO выдаёт трек агенту
1. Дай ссылку на репозиторий + страницу трека, напр. `github_project/tracks/frontend.md`.
2. Скажи: «Начни со следующей `todo` задачи (или группы подряд идущих `todo`).»
3. Агент читает `README.md` → `05_AGENT_PROTOCOL.md`, берёт задачу из трека, обновляет `04_STATUS_LOG.md`.

## Параллелизация (ключевое)
- **Фаза 0** — неделима, делается первой (каркас + схемы + статус-система).
- После фазы 0 **фронт (фаза 1) и бэкенд (фаза 10) могут идти одновременно разными агентами** — у них разные треки и разные папки (`client/` и `server/`), пересечение только через `shared/` (схемы/контракты).
- `shared` (фаза 3, движок сценариев) тоже может идти параллельно фронту — он не блокируется бэкендом, пока не нужен детерминизм турниров (`T034`, зависит от `T100`).
- `content` (фаза 11) стартует, как только готов движок сценариев (`T030/T044`); контент-агенты пишут параллельно фронту.
- `qa` — сквозной трек: пишет тесты по ходу и финальные гейты (фаза 12).

## Почему это работает без человека
- Каждый трек — самодостаточный набор задач в порядке.
- Общий контракт между треками — `shared/` (Zod-схемы, manifest, дизайн-токены). Меняешь контракт → меняешь версию, остальные треки адаптируются.
- Статус синхронизируется через `04_STATUS_LOG.md` + файлы задач; генератор пересобирает треки из `_meta/tasks.json`.

> Админ/CRM (`admin/`) — **отдельная будущая задача**, не часть текущей агентной разработки через GitHub. Там — управление игрой как контентом и сток данных; идея «агенты подключаются к CRM через API как отделы и чаты» планируется там же, но это **другая задача** (см. `admin/ADMIN_ROADMAP.md`).
